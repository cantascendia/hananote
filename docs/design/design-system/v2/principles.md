# Design Principles — HanaNote v2 Editorial East Asian

> Generated 2026-04-28 from candidate-A-editorial-east-asian.md
>
> 五条视觉语法 + 一份严禁清单。所有屏幕设计、组件 PR、Code Review 都按这套原则裁判。
> 当原则之间冲突时，**优先级从上到下递减**。

---

## 1. 一抹强色 (One Spot of Color)

**90% 单色 + 10% 黛蓝**。让强色稀缺到每出现一次都像句号。

黛蓝 `#1F3A5F` 是 v2 唯一的"识别色"——它锚定品牌，但**绝不泛滥**。

**硬规则**：
- 一屏可见区域内，黛蓝出现位置 **≤ 3 处**
- 黛蓝只用于：① 主 CTA 按钮 ② 当前焦点 / 选中态 ③ 章节段落标记（标题左侧 4px 竖线）
- 大块面积（> 屏宽 30%）的黛蓝只能出现在 Onboarding 第 5 屏「翻开」按钮、Today 庆祝时刻——日常不允许

**正例**：Today 屏顶部「早安」是墨色宋体（不是黛蓝）；只有底栏 active Tab 下方 2px 下划线 + 一个未服药条目左侧 4px 竖线 + 「记一次」按钮——共 3 处。

**反例**：把每个列表项左侧都加黛蓝竖线"显得规整"——黛蓝立刻贬值成普通分隔符，等于没有强色。

---

## 2. 调和层次胜过投影 (Tonal Layering Over Shadow)

**不靠投影、不靠边框、不靠渐变，只靠"纸的厚度"**。

层级靠 surface 阶差（4-6 个明度单位）表达。这是人眼"察觉但不刺眼"的阈值，正好是杂志页面"章节块面"和"内文页"的色阶差。

**硬规则**：
- 默认 elevation = 0（无投影）
- AppBar 区域 **不用** `BackdropFilter blur`（v1 在 13 个文件里手写 blur 是工程债）——改用 `surfaceContainerHigh` 实底 + 滚动时下方加 1px outline @ 30% 细线
- 仅 Bottom Sheet 允许 `elev-high`（opacity ≤ 6%，用 ink 色采样）
- 边框是最后的求助——除 outline 单一例外（focus 状态），其他场景用 surface 阶差替代实线

**正例**：一个 surfaceContainerLowest `#FBF8F2` 的"内文页"放在 background `#F4F1EA` 上，6 个明度单位差，肉眼可辨但无边框、无阴影、无圆角光晕。

**反例**：给卡片加 `0 8px 24px rgba(0,0,0,0.1)` "增加层次感"——立刻读成 Material You + Web2.0，杂志感全无。

---

## 3. 编辑级不对称 (Editorial Asymmetry)

杂志栅格永远不对称。**居中是默认懒惰**，v2 强制偏移。

**硬规则**：
- 顶部 hero 标题左对齐到 32px，右侧给 96px+ 留白（不是居中、不是两端对齐）
- 一屏只允许一个视觉重心，重心位置 **偏左 30% 或偏右 30%**，绝不居中
- 章节标题左侧加 4px 黛蓝竖线，**长度只覆盖标题首行**（不是分隔符，是"段落标记"）
- 列表项左侧留 32px 永久留白（用于偶尔出现的章节序号，如「01 / 用药」）
- Onboarding 输入框无外框，仅底部 1px outline 线（focus 时变 primary 2px）
- 段落首行不缩进（杂志风，区别于报纸）

**正例**：Today 顶部「早安」`display-xl` 宋体左对齐 32px，下方日期 `body-sm` 淡墨与之左对齐——右侧屏幕 70% 宽是空白。

**反例**：把页面标题居中、按钮全部 `MainAxisAlignment.center`、卡片在屏幕中央——这是 v1 信纸感，v2 立刻死。

---

## 4. 慢节奏与留白 (Slow Cadence & White Space)

**留白本身就是内容**。空间稀缺时，宁可截断信息也不要挤压。

间距系统故意跳过 12 和 20，强制设计师在「16 (md)」和「32 (lg)」之间二选一——没有"差不多介于两者之间"的偷懒选项。

**硬规则**：
- 相邻两个间距必须跨级（不允许 16 紧挨 16）
- Today 顶部留白 ≥ 64px（xl）才能开始第一行内容
- Onboarding 屏幕首屏到第一个内容块 ≥ 128px（xxl）
- 列表项之间用间距分隔，**不用分隔线**（24px 间距足够分离视觉单元）
- 庆祝反馈的"等待 0.4s"是仪式感的关键——不能立即 dismiss

**正例**：Today 屏 5 条用药条目之间各空 24px，无线无边框；点击「记一次」后屏幕静默 0.4s，再淡入「今日已记。」1.2s 淡出——总仪式 ~2.6s。

**反例**：信息密度优先把 5 条用药挤进半屏，每条加 1px 分隔线"清晰"——立刻读成 iOS Settings，杂志感全无。

---

## 5. 内容即装饰 (Content Is the Decoration)

**装饰存在于排版细节，不存在于额外元素**。宋体起笔的撇捺、tracking +0.6 的 label 间距、CJK 行高 1.7 的呼吸感——这些就是 v2 的全部装饰。

**硬规则**：
- **零 emoji**——所有用户可见文案（ARB / 通知 / 庆祝）都禁止使用 emoji（💊✅🌸 全部移除）
- **零粒子动画**——花瓣、星星、confetti、心心全部禁止
- **零渐变**——`LinearGradient` 在 v2 仅允许出现在照片占位符的内置功能上，不能 hand-roll
- **零图标 Tab 栏**——底栏 5 个 Tab **仅文字标签**，active Tab 用黛蓝下划线 2px（杂志目录页语法）
- 文案调性：第三人称编辑视角 + 句号收尾（"今日宜，按时。" / "今日已记。" / "本期空白。"）

**正例**：庆祝反馈是一行黑墨宋体「今日已记。」+ 1.2s 淡入淡出——四个字承担了 v1 整套花瓣粒子的情感重量。

**反例**：在「今日已记。」旁边加一个 ✓ 图标"让用户更清楚"——破坏宋体的克制感，立刻变成工具类 app。

## 严禁清单 (The Forbidden List)

下列在 v2 的 PR 中视为 **block reason**（不是 nit、不是 suggest——是 must-fix 才能 merge）：

| 禁止 | 原因 | 替代 |
|------|------|------|
| 粉色 / 樱花 / 花瓣装饰 | v1 花笺识别符号，v2 彻底切割 | 留白 + 一行宋体 |
| 二次元 / Gen-Z 渐变 | 不符合 22-35 岁成熟用户调性 | 单色基底 + 一抹黛蓝 |
| 圆角 ≥ 8px | 软糖造型，v2 全面收紧到 4px | r-card (4) / r-button (6) |
| BackdropFilter blur | 工程债 + 玻璃感错位（13 文件清理对象）| 实色 surfaceContainerHigh + 1px outline 滚动细线 |
| 投影 opacity > 6% | 破坏纸感 | elev-0 默认，靠 surface 阶差 |
| Stadium / pill button (默认场景) | Material 痕迹 | r-button 6px |
| Emoji（用户可见文案）| 调性错位 | 句号收尾的编辑文案 |
| Material You 动态色 | 算法派生会稀释黛蓝的稀缺感 | 手写 ColorScheme，不用 fromSeed |
| 图标式 Tab 栏 | iOS / Android 默认语法 | 文字 Tab + 下划线 |
| 第二人称鼓励文案（"你做到了！"）| v1 哄孩子调性 | 第三人称陈述（"今日已记。"）|

## 决策流程图

PR 中遇到设计争议时按此顺序判定：

1. 是否破坏「一抹强色」？ → 黛蓝 ≤ 3 处？大块黛蓝只在 Onboarding 第 5 屏 / 庆祝时刻？
2. 是否引入投影 / blur / 渐变？ → 替换为 surface 阶差
3. 是否居中布局？ → 改为左对齐 32px 或偏移 30%
4. 间距是否跨级？ → 16 不紧挨 16
5. 是否有 emoji / 图标装饰承担情感重量？ → 删除，让宋体本身说话

通过这 5 步的设计才进入 Code Review。任何一步失败 → request changes。
